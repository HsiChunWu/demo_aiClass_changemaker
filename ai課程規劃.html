n8n 基礎與 Google 憑證

AI 觀念建構 → n8n 工作流操作 → Google API 申請｜共 4 小時

第 1 節 AI 觀念建構：LLM、Agent、PSIO 與 Prompt 設計規範 1 小時 ▶

LLM vs AI Agent

LLMAI Agent
比喻百科全書式問答機會執行任務的助理
行為一問一答，無記憶多步驟、可呼叫工具、有記憶
例子ChatGPT 對話視窗n8n 工作流 + AI 節點
💡 類比：LLM 是「聰明的大腦」，Agent 是「有腦又有手腳的員工」

Prompt 設計規範

與 AI 對話前，先掌握這六條規範，才能穩定拿到好結果：

規範說明反例 → 正例
具體明確 避免模糊詞彙，說清楚預期結果 「寫得好一點」→「改為正式書信語氣，不超過 100 字」
提供脈絡 告訴 AI 背景資訊與限制條件 「幫我寫通知」→「這是寄給 40 歲以上學員的課前通知，需含時間地點」
指定格式 明確說明輸出要用什麼結構 「整理一下」→「輸出為 Markdown 表格，欄位：項目、說明、優先級」
正向描述 說「要什麼」而非「不要什麼」 「不要太難」→「使用國中程度的語彙說明」
分段給資料 長資料與指令明確分開 指令和資料混在一起 → 「指令寫在前，資料用『---』隔開後貼上」
一次一件事 複雜需求拆成多輪提問 一次要求翻譯＋摘要＋改寫 → 先翻譯，確認後再摘要
實作：講師示範同一需求用「不符規範」與「符合規範」各問一次，學員觀察差異

PSIO Prompt 撰寫框架

掌握規範後，用 PSIO 框架把需求結構化，讓每次 prompt 都有完整的骨架：

P — Purpose（目的） 推薦最適合初學者的資料分析課程 S — Step（步驟） 1. 閱讀課程清單 2. 評估難度與適合對象 3. 列出推薦 I — Input（輸入） 課程清單如下：[貼上課程資料] O — Output（輸出） 條列3門課，每門附上一句推薦理由（20字以內）

任務拆解練習

將「建立可以回答課程問題的機器人」拆解為 5 個步驟：

  1. 使用者輸入問題（Input 邊界定義）
  2. 判斷問題類型（分類任務）
  3. 查詢課程資料（資料來源）
  4. 組合回答（LLM 整合）
  5. 回傳給使用者（Output 格式）
每個步驟 = n8n 的一個節點

第 3 節 申請 Google 憑證 1.5 小時 ▶

逐步操作流程

  1. 進入 Google Cloud Console → 建立新專案「AI課程專案」
  2. 啟用 API：Gmail API、Google Sheets API、Google Drive API
  3. 建立 OAuth 2.0 憑證：應用程式類型選「網頁應用程式」，填入 n8n callback URL
  4. 在 n8n Credentials 貼上 Client ID 與 Client Secret → 授權

常見地雷

  • 測試帳號限制：OAuth 同意畫面須加入測試使用者才能授權
  • 範圍不足：回 API 頁面確認已啟用正確服務
  • 憑證過期：了解 token 自動更新機制

第 6 節 多案比較與提案資料標準化 45 分鐘 ▶

從單案到多案

提案受理者常面對多份格式不同的資料。這一節練習把多份資料整理成一致欄位，方便比較、彙整與回報。

比較欄位設計

比較面向觀察重點
服務對象是否重複、是否涵蓋不同族群、是否與計畫目標一致
課程主題主題分布、是否過度集中、是否有新興需求
資源需求人力、場地、設備、預算是否合理
預期成果成果是否具體、可追蹤、可回報
風險與缺漏資料不足、執行風險、需補問事項

產出多案比較表

  • 將多份提案整理成一致欄位
  • 比較不同提案的服務對象、課程主題、資源需求與預期成果
  • 找出共同亮點、明顯差異與需注意風險
  • 用「未提供」或「需補充」標示資料缺漏

多案比較 Prompt

「請根據以下多份單案資料卡，整理成多案比較表。 比較欄位包含： 1. 案件名稱 2. 提案單位 3. 服務對象 4. 課程主題 5. 執行方式 6. 資源需求 7. 預期成果 8. 主要亮點 9. 主要風險 10. 資料缺漏 11. 建議追問事項 請在表格後方補充： 1. 共同亮點 2. 主要差異 3. 值得優先確認的風險 請不要加入原資料沒有支持的判斷。」

多案比較欄位設計

欄位比較目的
服務對象確認資源是否重複集中或有服務缺口
執行方式比較各案操作難度與可複製性
資源需求觀察人力、場地、設備與預算壓力
主要亮點萃取可向上回報的成果與特色
建議追問事項形成後續補件或訪談問題
實作：用 3 至 5 份範例提案產出多案比較表，作為後續分析報告的基礎

提案資料彙整 Skill 欄位設計

欄位內容
Skill 名稱提案資料彙整與分析報告 Skill
使用時機收到多份課程提案、成果資料或問卷回饋，需要整理成分析報告前使用

後端代理 Cloudflare Worker 概念

實務上，前端頁面通常不會直接把重要網址、金鑰或複雜判斷暴露給使用者。Cloudflare Worker 可以作為很薄的一層後端代理：前端把請求送到 Worker，Worker 再轉送到 n8n、API 或其他服務，並負責基本檢查、隱藏敏感資訊與處理跨網域限制。

本課程不實作 Cloudflare Worker，只讓學員理解「前端頁面」和「真正後端服務」之間有時會需要一層代理。課堂實作仍以 HTML 前端直接串接 n8n Webhook 為主。

關鍵字 vs 語意搜尋

搜尋方式行為結果範例

Embedding 是什麼？

💡 類比：把每一段文字轉換成一串數字（座標），意思相近的文字在「空間中」距離很近。搜尋時就是找距離最近的幾個座標。
文字 → Embedding 模型 → 向量（數字陣列） 「Python 入門課」 → [0.12, -0.45, 0.87, ...] 「初學者程式課程」 → [0.11, -0.43, 0.85, ...] ← 距離很近 「咖啡豆烘焙技術」 → [0.72, 0.31, -0.20, ...] ← 距離很遠

第一步：建立 Qdrant 知識庫（30 分鐘）Optional

  1. 註冊 Qdrant Cloud 免費帳號，建立新 Cluster
  2. 取得 API Key 與 Cluster URL，填入 n8n Credentials

第二步：主查詢工作流節點配置（60 分鐘）

節點設定重點
① Webhook接收 { name, question }
② Set整理 userName、userQuestion 變數
③ OpenAI Embeddings將 userQuestion 轉換成向量
④ Qdrant 向量搜尋語意搜尋，回傳相似度最高 3 筆課程
⑤ Set（組合 context）將 3 筆課程內容組合成 context 文字
⑥ OpenAI Chat ModelPSIO system prompt + context 注入
⑦ Respond to Webhook回傳 { reply, courses }

System Prompt 設計（PSIO）

P — Purpose 回答使用者的課程查詢，給出準確的推薦 S — Step 1. 閱讀提供的課程資料 2. 對應使用者問題 3. 選出最相關課程 I — Input 使用者：{userName}，問題：{userQuestion} 課程資料（來自 Qdrant 語意搜尋）：{context} O — Output 推薦 1-3 門課程，每門包含名稱和推薦說明（50字以內）

第三步：基本錯誤處理（30 分鐘）

  • 找不到相關課程時的 fallback 回覆（IF 節點判斷搜尋結果是否為空）
  • 使用者輸入為空時的早期攔截（在 Webhook 後加 IF 節點）
  • n8n 執行記錄查看：如何從錯誤訊息找到哪個節點出問題
  • 實測：故意輸入奇怪的問題，觀察系統回應

第 12 節 第三階段 B 開始：MCP 概念與 Chrome DevTools MCP 設定 1 小時 ▶

MCP 是什麼

MCP 可以理解成 AI 助理與外部工具之間的標準接口。前面 Codex 主要讀取檔案與修改程式；加入 Chrome DevTools MCP 後，Codex 可以透過真實 Chrome 瀏覽器協助檢查畫面、Console、Network、截圖與互動狀態。

Node.js 與 npm 檢查

步驟說明
檢查 Node.js在 VS Code Terminal 輸入 node -v，若出現版本號代表已安裝
檢查 npm在 VS Code Terminal 輸入 npm -v，若出現版本號代表可使用 npm 套件
Windows 未安裝到 Node.js 官方網站下載 LTS 版安裝檔，安裝時保留預設選項，完成後重新啟動 VS Code
macOS 未安裝到 Node.js 官方網站下載 LTS 版安裝檔，或使用 Homebrew 安裝 Node.js，完成後重新啟動 VS Code
仍找不到指令關閉並重開 VS Code 與 Terminal；若仍失敗，檢查 Node.js 是否加入系統 PATH

用 Codex VSCode Extension 加入 Chrome DevTools MCP

  1. 開啟 VS Code，確認已安裝並登入 Codex VSCode Extension
  2. 開啟 Codex 側邊欄，進入設定或工具設定區，找到 MCP Servers / Tools 相關入口
  3. 選擇新增 MCP server，類型選擇本機指令、stdio 或 command server
  4. Server name 填入 chrome-devtools
  5. Command 填入 npx
  6. Arguments 依序新增兩個值：-y、chrome-devtools-mcp
  7. 儲存設定，回到 Codex 側邊欄重新整理工具清單；必要時重新啟動 VS Code
  8. 確認 Codex 工具清單中出現 Chrome DevTools 相關能力，例如開啟頁面、截圖、Console、Network 或 Lighthouse
  9. 請 Codex 測試：「請開啟目前的 HTML 頁面，幫我檢查 Console 是否有錯誤，並截圖確認畫面是否正常。」
課堂以 Codex VSCode Extension 的視窗介面操作為主：在 Codex 的 MCP / Tools 設定中新增 server，填入 name、command、arguments，不使用命令列加入設定。

分段 Prompt 策略

Prompt 1：基本結構 「建立課程查詢頁面：標題、姓名欄位、問題輸入框（多行）、送出按鈕」 Prompt 2：串接後端 「加入送出功能：POST 資料到 [n8n URL]，顯示 loading，成功後顯示 reply 欄位」 Prompt 3：結果展示 「回傳的 JSON 包含 reply（文字）和 courses（陣列）， reply 顯示在上方，courses 以卡片方式列在下方」 Prompt 4：視覺優化 「整體風格參考教育機構網站，主色藍色，卡片有陰影，RWD 支援手機」
