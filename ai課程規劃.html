n8n 基礎與 Google 憑證

AI 觀念建構 → n8n 工作流操作 → Google API 申請｜共 4 小時

第 1 節 AI 觀念建構：LLM、Agent、PSIO 與 Prompt 設計規範 1 小時 ▶

LLM vs AI Agent

LLMAI Agent
比喻百科全書式問答機會執行任務的助理
行為一問一答，無記憶多步驟、可呼叫工具、有記憶
例子ChatGPT 對話視窗n8n 工作流 + AI 節點
💡 類比：LLM 是「聰明的大腦」，Agent 是「有腦又有手腳的員工」

Prompt 設計規範

與 AI 對話前，先掌握這六條規範，才能穩定拿到好結果：

規範說明反例 → 正例
具體明確 避免模糊詞彙，說清楚預期結果 「寫得好一點」→「改為正式書信語氣，不超過 100 字」
提供脈絡 告訴 AI 背景資訊與限制條件 「幫我寫通知」→「這是寄給 40 歲以上學員的課前通知，需含時間地點」
指定格式 明確說明輸出要用什麼結構 「整理一下」→「輸出為 Markdown 表格，欄位：項目、說明、優先級」
正向描述 說「要什麼」而非「不要什麼」 「不要太難」→「使用國中程度的語彙說明」
分段給資料 長資料與指令明確分開 指令和資料混在一起 → 「指令寫在前，資料用『---』隔開後貼上」
一次一件事 複雜需求拆成多輪提問 一次要求翻譯＋摘要＋改寫 → 先翻譯，確認後再摘要
實作：講師示範同一需求用「不符規範」與「符合規範」各問一次，學員觀察差異

PSIO Prompt 撰寫框架

掌握規範後，用 PSIO 框架把需求結構化，讓每次 prompt 都有完整的骨架：

P — Purpose（目的） 推薦最適合初學者的資料分析課程 S — Step（步驟） 1. 閱讀課程清單 2. 評估難度與適合對象 3. 列出推薦 I — Input（輸入） 課程清單如下：[貼上課程資料] O — Output（輸出） 條列3門課，每門附上一句推薦理由（20字以內）

任務拆解練習

將「建立可以回答課程問題的機器人」拆解為 5 個步驟：

  1. 使用者輸入問題（Input 邊界定義）
  2. 判斷問題類型（分類任務）
  3. 查詢課程資料（資料來源）
  4. 組合回答（LLM 整合）
  5. 回傳給使用者（Output 格式）
每個步驟 = n8n 的一個節點
第 2 節 n8n 介面操作與簡易對話工作流 1.5 小時 ▶

環境設定

  • 使用 n8n Cloud（免安裝，新手友善）
  • 介面說明：畫布、節點庫、執行記錄面板

核心節點介紹

節點用途類比
Chat Trigger啟動對話，提供內建聊天介面接待人員開啟對話窗口
Set整理 / 轉換資料填寫表單格式
IF條件判斷主管決策
AI Agent呼叫 LLM，可搭配工具與記憶交給 AI 員工處理
Webhook接收外部 HTTP 請求公司對外收件信箱

實作：簡易對話工作流

[Chat Trigger] ── 內建聊天介面，直接在 n8n 測試 ↓ [AI Agent] ── 設定 system prompt（用 PSIO 框架撰寫） ↓ （Chat Trigger 自動處理回傳，不需另加節點）
優點：不需 Postman，直接在 n8n 畫布右側開啟聊天視窗測試
第 3 節 申請 Google 憑證 1.5 小時 ▶

逐步操作流程

  1. 進入 Google Cloud Console → 建立新專案「AI課程專案」
  2. 啟用 API：Gmail API、Google Sheets API、Google Drive API
  3. 建立 OAuth 2.0 憑證：應用程式類型選「網頁應用程式」，填入 n8n callback URL
  4. 在 n8n Credentials 貼上 Client ID 與 Client Secret → 授權

常見地雷

  • 測試帳號限制：OAuth 同意畫面須加入測試使用者才能授權
  • 範圍不足：回 API 頁面確認已啟用正確服務
  • 憑證過期：了解 token 自動更新機制

VSCode × Codex 前端開發

對話策略 → 漸進式實作 → 資料清理與報告撰寫｜共 4 小時

第 4 節 與模型對話的方式 1 小時 ▶

對話心態建立

  • AI 是「可以討論的協作者」，不是搜尋引擎
  • 不用第一次就說完整，可以漸進補充
  • 錯了繼續說「修改剛才的…」，不需重新開始

三層次對話策略

── 層次1：直接描述 ── 「幫我寫一個有姓名和信箱欄位的 HTML 表單」 ── 層次2：加上限制條件 ── 「幫我寫一個 HTML 表單，有姓名和信箱欄位， 用藍色主題，送出按鈕在右下角」 ── 層次3：PSIO 完整 Prompt ── 「目的：建立一個課程查詢頁面。 步驟：先規劃 HTML 結構，再加入 CSS 樣式。 輸入：姓名輸入框、多行問題輸入框、送出按鈕。 輸出：完整可執行的單一 HTML 檔案，風格簡潔專業。」
實作：學員用三種層次各寫一個 prompt，比較產出品質差異

每個範例在前一個基礎上累加，聚焦在前端本身的能力，不串接後端。

第 6 節 清理撰寫成果報告所需的資料 1 小時 ▶

為什麼需要資料清理？

課程結束後通常會留下雜亂的原始資料：學員問答記錄、操作截圖說明、Google Sheets 的填答結果。這些資料需要先整理，AI 才能幫你產出有品質的報告。

第一步：整理原始資料（25 分鐘）

Prompt 範例：資料清洗 「以下是學員問答記錄，格式不一致。 請幫我：1. 移除重複的問題 2. 統一問題的句型為疑問句 3. 將問題依主題分類（操作類、觀念類、其他） 4. 輸出為表格格式（欄位：類別、問題、出現次數）」

常見原始資料類型與清理重點

資料類型常見問題清理方向
問答記錄重複、格式混亂、口語化去重、分類、標準化語句
操作截圖說明說明文字零散、缺少脈絡統一格式：步驟編號＋說明
學員填答結果空白欄位、中英混用補全、統一語言、去除無效填答

第二步：萃取報告關鍵資訊（20 分鐘）

Prompt 範例：資訊萃取 「根據以下清理後的問答記錄，幫我找出： 1. 學員最常問的前3個問題 2. 最多人卡關的操作步驟 3. 對課程最正面的回饋關鍵詞（列出前5個） 輸出格式：每項用標題 + 2句說明」

第三步：確認資料完整性（15 分鐘）

  • 確認每個報告章節都有對應的素材（數字、範例、截圖清單）
  • 缺少的部分用 AI 標記：「以下哪些欄位資料不足，需要補充？」
  • 完成後：資料夾整理好，準備下一階段撰寫報告
實作：學員用提供的範本原始資料，產出一份可直接用於報告的結構化素材包

第 7 節 向量資料庫概念介紹 1 小時 ▶

關鍵字 vs 語意搜尋

搜尋方式行為結果範例
關鍵字搜尋找完全一樣的字搜尋「Python課程」只找到標題含 Python 的
語意搜尋（向量）找意思最接近的搜尋「適合初學者的程式課」→ 找到 Python、Scratch、視覺化工具等

Embedding 是什麼？

💡 類比：把每一段文字轉換成一串數字（座標），意思相近的文字在「空間中」距離很近。搜尋時就是找距離最近的幾個座標。
文字 → Embedding 模型 → 向量（數字陣列） 「Python 入門課」 → [0.12, -0.45, 0.87, ...] 「初學者程式課程」 → [0.11, -0.43, 0.85, ...] ← 距離很近 「咖啡豆烘焙技術」 → [0.72, 0.31, -0.20, ...] ← 距離很遠

常見向量資料庫比較

工具特色適合場景
Qdrant開源、效能高、n8n 原生支援本課程使用，適合實作練習
Pinecone全托管雲端服務，免建置快速上線的商業應用
Supabase pgvector整合在 PostgreSQL 中已有 Supabase 資料庫的專案
Chroma輕量、本機執行本地開發、原型測試

整合到課程系統的角色

課程資料 → Embedding → 存入 Qdrant （一次性建立知識庫） 使用者問題 → Embedding → 在 Qdrant 搜尋最相近的課程 （每次查詢時執行）
第 8 節 n8n 查詢工作流建立 2.5 小時 ▶

第一步：建立 Qdrant 知識庫（30 分鐘）Optional

  1. 註冊 Qdrant Cloud 免費帳號，建立新 Cluster
  2. 取得 API Key 與 Cluster URL，填入 n8n Credentials
  3. 在 n8n 建立「資料匯入流程」：手動觸發 → 讀取課程 JSON → OpenAI Embeddings → Qdrant 插入節點
  4. 執行一次，確認課程資料已存入 Qdrant Collection
課程資料（約 20 筆）由講師預先準備，學員直接匯入即可，聚焦在流程理解

第二步：主查詢工作流節點配置（1 小時）

節點設定重點
① Webhook接收 { name, question }
② Set整理 userName、userQuestion 變數
③ OpenAI Embeddings將 userQuestion 轉換成向量
④ Qdrant 向量搜尋語意搜尋，回傳相似度最高 3 筆課程
⑤ Set（組合 context）將 3 筆課程內容組合成 context 文字
⑥ OpenAI Chat ModelPSIO system prompt + context 注入
⑦ Respond to Webhook回傳 { reply, courses }

System Prompt 設計（PSIO）

P — Purpose 回答使用者的課程查詢，給出準確的推薦 S — Step 1. 閱讀提供的課程資料 2. 對應使用者問題 3. 選出最相關課程 I — Input 使用者：{userName}，問題：{userQuestion} 課程資料（來自 Qdrant 語意搜尋）：{context} O — Output 推薦 1-3 門課程，每門包含名稱和推薦說明（50字以內）

第三步：錯誤處理補強（1 小時）

  • 找不到相關課程時的 fallback 回覆（IF 節點判斷搜尋結果是否為空）
  • 使用者輸入為空時的早期攔截（在 Webhook 後加 IF 節點）
  • n8n 執行記錄查看：如何從錯誤訊息找到哪個節點出問題
  • 實測：故意輸入奇怪的問題，觀察系統回應
第 9 節 前端整合 1.5 小時 ▶

分段 Prompt 策略

Prompt 1：基本結構 「建立課程查詢頁面：標題、姓名欄位、問題輸入框（多行）、送出按鈕」 Prompt 2：串接後端 「加入送出功能：POST 資料到 [n8n URL]，顯示 loading，成功後顯示 reply 欄位」 Prompt 3：結果展示 「回傳的 JSON 包含 reply（文字）和 courses（陣列）， reply 顯示在上方，courses 以卡片方式列在下方」 Prompt 4：視覺優化 「整體風格參考教育機構網站，主色藍色，卡片有陰影，RWD 支援手機」

前後端串接測試

  • 用 n8n 執行記錄確認資料流正確
  • 測試邊界：問非課程相關問題、問題超長
  • 用 Codex 修正實際遇到的 CORS 等問題
