n8n 基礎與 Google 憑證

AI 觀念建構 → n8n 工作流操作 → Google API 申請｜共 4 小時

第 1 節 AI 觀念建構：LLM、Agent、Prompt 規範與 PSIO 框架 1 小時 ▶

LLM vs AI Agent

LLMAI Agent
比喻百科全書式問答機會執行任務的助理
行為一問一答，無記憶多步驟、可呼叫工具、有記憶
例子ChatGPT 對話視窗n8n 工作流 + AI 節點
💡 LLM 是「聰明的大腦」，Agent 是「有腦又有手腳的員工」

Prompt 設計規範

規範說明反例 → 正例
具體明確避免模糊詞彙「寫得好一點」→「改為正式語氣，不超過 100 字」
提供脈絡給背景與限制條件「幫我寫通知」→「寄給 40 歲以上學員的課前通知，需含時間地點」
指定格式說明輸出結構「整理一下」→「輸出為 Markdown 表格，欄位：項目、說明、優先級」
正向描述說要什麼，不說不要什麼「不要太難」→「使用國中程度的語彙說明」
分段給資料指令與資料明確分開混在一起 → 「指令在前，資料用『---』隔開後貼上」
一次一件事複雜需求拆成多輪一次要求翻譯＋摘要＋改寫 → 先翻譯，確認後再摘要
實作：講師示範同一需求用「不符規範」與「符合規範」各問一次，觀察差異

PSIO Prompt 撰寫框架

P — Purpose（目的） 推薦最適合初學者的資料分析課程 S — Step（步驟） 1. 閱讀課程清單 2. 評估難度與適合對象 3. 列出推薦 I — Input（輸入） 課程清單如下：[貼上課程資料] O — Output（輸出） 條列3門課，每門附上一句推薦理由（20字以內）

任務拆解練習

  1. 使用者輸入問題（Input 邊界定義）
  2. 判斷問題類型（分類任務）
  3. 查詢課程資料（資料來源）
  4. 組合回答（LLM 整合）
  5. 回傳給使用者（Output 格式）
每個步驟 = n8n 的一個節點
第 2 節 n8n 介面操作與簡易對話工作流 1.5 小時 ▶

環境設定

  • 使用 n8n Cloud（免安裝，新手友善）
  • 介面說明：畫布、節點庫、執行記錄面板

核心節點介紹

節點用途類比
Chat Trigger啟動對話，提供內建聊天介面接待人員開啟對話窗口
Set整理 / 轉換資料填寫表單格式
IF條件判斷主管決策
AI Agent呼叫 LLM，可搭配工具與記憶交給 AI 員工處理
Webhook接收外部 HTTP 請求公司對外收件信箱

實作：簡易對話工作流

[Chat Trigger] ── 內建聊天介面，直接在 n8n 測試 ↓ [AI Agent] ── 設定 system prompt（用 PSIO 框架撰寫） ↓ （Chat Trigger 自動處理回傳，不需另加節點）
優點：不需 Postman，直接在 n8n 畫布右側開啟聊天視窗測試
第 3 節 申請 Google 憑證 1.5 小時 ▶

逐步操作流程

  1. 進入 Google Cloud Console → 建立新專案「AI課程專案」
  2. 啟用 API：Gmail API、Google Sheets API、Google Drive API
  3. 建立 OAuth 2.0 憑證：應用程式類型選「網頁應用程式」，填入 n8n callback URL
  4. 在 n8n Credentials 貼上 Client ID 與 Client Secret → 授權

常見地雷

  • 測試帳號限制：OAuth 同意畫面須加入測試使用者才能授權
  • 範圍不足：回 API 頁面確認已啟用正確服務
  • 憑證過期：了解 token 自動更新機制

第 5 節 向量資料庫概念介紹（壓縮版） 0.5 小時 ▶

關鍵字 vs 語意搜尋

搜尋方式行為結果範例
關鍵字搜尋找完全一樣的字「Python課程」只找標題含 Python 的
語意搜尋（向量）找意思最接近的「適合初學者的程式課」→ 找到 Python、Scratch 等
💡 把文字轉成數字座標，意思相近的距離近，搜尋時找最近的幾筆。本課程使用 Qdrant（開源、n8n 原生支援）。
第 6 節 n8n 查詢工作流建立 2.5 小時 ▶

第一步：建立 Qdrant 知識庫（30 分鐘）Optional

  1. Qdrant Cloud 帳號建立，建立新 Cluster
  2. 取得 API Key 與 Cluster URL，填入 n8n Credentials
  3. 建立資料匯入流程：手動觸發 → 課程 JSON → OpenAI Embeddings → Qdrant 插入
  4. 執行確認資料存入
講師預先準備約 20 筆課程資料，學員直接匯入

第二步：主查詢工作流（1 小時）

節點設定重點
① Webhook接收 { name, question }，設定 Header Auth
② Set整理 userName、userQuestion 變數
③ OpenAI Embeddings將 userQuestion 轉換成向量
④ Qdrant 向量搜尋語意搜尋，回傳相似度最高 3 筆課程
⑤ Set（組合 context）將 3 筆課程組合成 context 文字
⑥ OpenAI Chat ModelPSIO system prompt + context 注入
⑦ Google Sheets記錄查詢時間、問題長度、成功與否
⑧ Respond to Webhook回傳 { reply, courses }

System Prompt（PSIO）

P — Purpose 回答使用者課程查詢，給出準確推薦 S — Step 1. 閱讀課程資料 2. 對應問題 3. 選最相關課程 I — Input 使用者：{userName}，問題：{userQuestion} 課程資料（Qdrant 搜尋結果）：{context} O — Output 推薦 1-3 門，每門含名稱和說明（50字以內） 回答限制在 300 字以內。只根據提供資料回答，不自行編造課程。

第三步：錯誤處理（1 小時）

  • 搜尋結果為空時的 fallback 回覆
  • 使用者輸入為空的早期攔截
  • n8n 執行記錄查看與除錯
第 7 節 前端整合 2 小時 ▶

分段 Prompt 策略

Prompt 1：基本結構 「建立課程查詢頁面：標題、姓名欄位、問題輸入框（多行）、送出按鈕」 Prompt 2：串接後端（先直連 n8n 測試） 「加入送出功能：POST 資料到 [n8n URL]，顯示 loading，成功後顯示 reply」 Prompt 3：結果展示 「回傳 JSON 含 reply 和 courses 陣列，reply 顯示上方，courses 以卡片列在下方」 Prompt 4：視覺優化 「教育機構風格，主色藍色，RWD 支援手機，卡片有陰影」 Prompt 5：個資告知（正式上線需要） 「在送出按鈕下方加一行小字： 送出後，系統會記錄你的問題內容，用於課程回覆與服務改善。 請勿輸入敏感個人資訊。」
此階段前端先直連 n8n 驗證功能，第 8 節改為 Worker URL 並加入 Turnstile
第 8 節 Cloudflare Worker 完整安全部署 3.5 小時 ▶

第一部分：安全架構全覽（30 分鐘）

安全層保護什麼本節實作
Origin 限制只允許自己的前端呼叫✅ 課堂帶做
CORS preflight瀏覽器跨域請求管控✅ 課堂帶做
n8n Header Auth防止繞過 Worker 直連 n8n✅ 課堂帶做
Turnstile 人機驗證防止機器人批次呼叫✅ 課堂帶做
Rate Limit防止同一 IP 濫用✅ 課堂帶做
輸入驗證防止超長輸入燒 token✅ 課堂帶做
成本控管OpenAI token 上限設定✅ 課堂帶做
Staging/Production 分離改動不影響正式服務✅ 課堂帶做

第二部分：建立 Worker 代理 + CORS + Origin（60 分鐘）

  1. Cloudflare 帳號建立，進入 Workers & Pages → 建立 Worker
  2. 貼入講師提供的範本程式碼
  3. 設定 Worker Secrets：N8N_WEBHOOK_URL、N8N_PROXY_SECRET
  4. 設定允許的 Origin：填入 GitHub Pages 網址
  5. 確認 OPTIONS preflight 正確回應 204
  6. Deploy，取得 Worker URL
// Worker 核心邏輯（範本已提供，此處說明原理） if (!allowedOrigins.includes(origin)) return 403 Forbidden if (method === "OPTIONS") return corsHeaders + 204 No Content if (method !== "POST") return 405 Method Not Allowed // 驗證通過後，加上 secret header 轉送 n8n fetch(N8N_WEBHOOK_URL, { headers: { "X-Proxy-Secret": N8N_PROXY_SECRET } })

第三部分：n8n Header Auth 設定（30 分鐘）

  1. n8n Webhook 節點 → Authentication → Header Auth
  2. Header Name：X-Proxy-Secret，Value：一串隨機密碼
  3. Worker Secret 填入相同密碼
  4. 前端 API URL 改為 Worker URL，測試是否仍正常回應

第四部分：Cloudflare Turnstile 人機驗證（30 分鐘）

  1. Cloudflare Dashboard → Turnstile → 建立 Site，取得 Site Key 與 Secret Key
  2. 前端加入 Turnstile widget（貼入一段 HTML + script）
  3. 送出表單時，將 Turnstile token 一起 POST 給 Worker
  4. Worker 加入 Turnstile 驗證邏輯：呼叫 Cloudflare API 確認 token 有效
  5. Worker Secret 新增：TURNSTILE_SECRET_KEY
Turnstile 是 Cloudflare 提供的免費人機驗證，比 reCAPTCHA 更簡潔，不需用戶勾選

第五部分：Rate Limit + 輸入驗證 + 成本控管（30 分鐘）

Rate Limit（Worker 層）

建議最低限制（已寫入範本，調整數字即可）： 同一 IP：每分鐘 5 次 同一 IP：每天 50 次 單題長度：500 字以內

成本控管（n8n + OpenAI）

  • OpenAI Dashboard 設定 Monthly Budget（月度費用上限）
  • System Prompt 加入：「回答限制在 300 字以內」
  • Qdrant 搜尋只回傳 top-3，不傳多餘 context
  • n8n 加入錯誤分支：連續失敗時回傳維護訊息，避免重試燒費用

第六部分：監控記錄 + 個資告知 + Staging/Production（30 分鐘）

查詢記錄（n8n → Google Sheets）

記錄欄位用途
timestamp查詢時間
name使用者姓名
question_length問題字數
success是否成功回覆
error_code失敗原因代碼
注意：記錄姓名與問題屬個人資料，頁面需加入告知文字（第 7 節 Prompt 5 已完成）

Staging / Production 分離

各建兩份，互不影響： GitHub Pages：ai-course-staging/ vs ai-course/ Cloudflare Worker：course-api-staging vs course-api n8n workflow：課程查詢測試版 vs 課程查詢正式版 Qdrant collection：courses_staging vs courses_production
流程：先在 staging 改功能 → 測試 10-20 次 → 確認無誤 → 套到 production

正式上線檢查表

  • 前端沒有任何 secret（n8n URL、API Key 等）
  • 前端只呼叫 Worker，不直連 n8n
  • Worker 限制 Origin
  • Worker 處理 OPTIONS preflight
  • Worker 驗證 Turnstile token
  • Worker 有 Rate Limit
  • Worker 檢查輸入長度
  • n8n Webhook 使用 Header Auth
  • OpenAI 有月度費用上限
  • 查詢記錄有個資告知
  • Staging 和 Production 分開
